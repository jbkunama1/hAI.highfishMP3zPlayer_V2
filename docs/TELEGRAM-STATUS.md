# Telegram-Startmeldung und Tagesstatus

Neue Portainer-Variablen: TELEGRAM_STATUS_CHAT_ID (genau eine numerische private Benutzer-ID aus TELEGRAM_ALLOWED_USER_IDS) und TELEGRAM_STATUS_TIMEZONE=Europe/Berlin. TELEGRAM_ENABLED=true und gueltiger Bot-Token bleiben erforderlich. Chat-ID leer: keine automatischen Statusmeldungen; kein Versand an die gesamte Allowlist. Den Bot im privaten Chat zuerst mit /start freischalten. Keine echten Chat-IDs/Token im Repository speichern.

Nach erfolgreicher HTTP-Bereitschaft auf /api/ping wird eine Startmeldung versucht. Index kann dabei noch im Aufbau sein; die Nachricht benennt diesen Zustand. Danach taeglich um 22:00 in der konfigurierten Zeitzone, inklusive Sommer-/Winterzeit. Python tzdata ist als Abhaengigkeit ergaenzt. Inhalt: Anlass, lokale Zeit, HTTP-Bereitschaft, Prozesslaufzeit, Dateizahl im Index, Storage-Modus und Indexaktivitaet. Keine absoluten Pfade, Zugangsdaten oder vollstaendigen Konfigurationen.

Maximal drei Zustellversuche mit Wartezeit, bei Telegram-Fehlern retry_after beachten. Keine Garantie exakt einmal: bei verlorener HTTP-Bestaetigung koennen Wiederholungen entstehen. Neustart erzeugt eine neue Startmeldung; vergangene 22-Uhr-Berichte werden nicht nachgeholt. Dienst muss zur geplanten Zeit laufen. Scheduler und Empfaenger liegen im Prozess, keine persistente Jobdatenbank. Eine Instanz pro Bot-Token betreiben. Bereits laufende Streams und echte SMB-Verfuegbarkeit werden durch den Status nicht vollstaendig getestet; HTTP bereit ist kein umfassender Healthcheck. Statusfehler stoppen den Player nicht.

PUBLIC_URL ist jetzt fuer Telegram optional: leer bedeutet Bot ohne Webplayer-URL-Buttons. Die bestehenden Bot-Funktionen werden ueber RuntimeBot wiederverwendet. Eine nichtleere URL wird weiter als HTTPS-Origin validiert; bei ungueltiger Botkonfiguration wird nur Telegram mit neutraler Warnung deaktiviert, Player/MCP laufen weiter. get_stream_link braucht weiterhin eine gueltige PUBLIC_URL. Alte telegram_bot.start_bot bleibt im Quellcode, wird vom produktiven cover_app.py aber nicht mehr verwendet.

Sieben lokale Tests mit gemockten Bot-Abhaengigkeiten/Versand: Planung heute/morgen, Sommer/Winter, Empfaengerbindung, optionale URL/Buttons, Konfigurationsfehler, Statusinhalt und Retry. Keine echte Telegram-Nachricht und kein Deployment ausgefuehrt. Nach Image-Build und Stack-Update Startmeldung und naechsten Tagesstatus praktisch pruefen. Empfaenger muss in Portainer selbst eingetragen werden, bis dahin ist keine automatische Zustellung eingerichtet.
